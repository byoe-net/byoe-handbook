# 卜一智航 (BYOE) 技能 (Skills) 管理与使用指南

在 BYOE (Bring Your Own Executive AI) 中，**Skills（技能）** 是赋予 AI Agent 长期记忆、专业领域知识以及自动化扩展能力的核心机制。

本文档将详细介绍如何将外部网上的优秀经验（Prompt 或代码）作为 Skill 导入系统，以及如何让 AI 在协作过程中自主沉淀和保存工作经验。

---

## 🎭 什么是 BYOE Skills？

在 BYOE 架构中，Skill 分为两种形态：

1. **认知型技能（Prompt Skills）**：以 JSON 格式存储的系统级长提示词。用于告诉 AI 遇到特定的 `trigger`（触发词）时，默认采取什么样的分析框架、代码审查标准或领域规范。
2. **动作型技能（Python Tool Skills）**：以 Python 脚本 (`.py`) 格式存储的动态工具代码。可以通过 AI 直接加载到上下文中，成为它可以直接调用的真实函数执行动作（Tool 操作）。

无论是哪种形态，它们默认都存放于用户系统的 **`~/.byoe/skills/`** 目录下。

---

## 一、如何使用外部导入的 Skills？

当你从开源社区、网上文章或其他团队那里获得了一套优秀的 Prompt 框架，或是好用的辅助脚本时，可以通过以下方式导入：

### 1. 导入认知型技能 (Prompt-based)

直接在 `~/.byoe/skills/` 目录下创建一个 `.json` 文件（例如 `code-reviewer.json`），其基本结构如下：

```json
{
  "name": "code-reviewer",
  "description": "前端 React 代码审查专家视图",
  "instructions": "当你进行代码审查时，请务必检查以下几点：\n1. 是否滥用了 useEffect...\n2. 组件是否具备良好的 Memo 缓存...\n3. CSS 类名是否符合 BEM 规范。",
  "trigger": "帮我 review 一下代码",
  "created_at": "2026-06-27T12:00:00Z",
  "builtin": false
}
```

**生效方式**：无需重启引擎，AI 在解析到用户对话包含 `trigger` 或你主动请求相关任务时，会自动拉取该预设知识。你也可以在 BYOE Web Dashboard 面板中直接可视化新增和粘贴这些设定。

### 2. 导入动作型技能 (Python Script-based)

如果你在网上看到了一个非常棒的自动化处理脚本（比如：批量将当前目录所有 png 压缩转 WebP 的脚本代码），你可以将其封装为动作型技能：

在 `~/.byoe/skills/` 下新建一个 `.py` 文件（例如 `convert_webp.py`）。文件内必须暴露出一个入口函数 `run`：

```python
# ~/.byoe/skills/convert_webp.py
import os

def run(directory: str = ".", **kwargs) -> str:
    """将目标目录下的所有图片自动化处理为 webp 格式"""
    count = 0
    # ... 省略具体的业务转换逻辑 ...
    return f"成功处理了 {count} 张图片！"
```

**生效方式**：在对话中，你可以直接告诉大模型：“请加载 `convert_webp` 技能并将 `./assets` 的图片转换”。AI 会使用内部的 `load_skill` (由 `skills_runtime.py` 驱动) 机制动态挂载该文件，并在后续直接作为原生的 Tool 参数来调用。

## 二、在使用过程中让系统沉淀经验

BYOE 最强大的特性在于 **运行时自我进化**。你不需要每次都人工去手写这些 Skill 文件，完全可以使唤 Agent 帮你将走通的复杂流程沉淀下来。

### 1. 引导 AI 固化工作流规范 (自动生成 Prompt Skill)
当你和 AI 经过多轮对话，打磨出了一个非常完美的“数据库表结构设计规范”后，你可以直接说：
> **用户**：“干得漂亮。请把我们刚才总结的这套数据库设计规范，保存为一个名为 `db-design-standard` 的技能，触发词设定为‘设计新表’。”

此时，AI 会自主调用底层的 `save_skill` 接口，自动帮你把之前聊天的上下文提炼成 `instructions` 并生成 JSON 到本地。下次遇到设计结构的需求时，无需重复背景交代，这套规范就会自动生效。

### 2. 引导 AI 固化自动化动作 (自动生成 Python Skill)
如果你让 AI 帮你写了一段极其复杂的项目启动诊断脚本（检查端口是否被占用、拉取并验证 Docker 配置、清理冗余缓存等）。代码在它手里跑通验证后，你可以说：
> **用户**：“刚才这个环境清理和自检的操作流很好用。以后你在排查启动失败时都会用到它。请把它封装成名为 `project_doctor` 的技能存下来。”

AI 会立即调用底层的 `create_skill` 工具：
1. 自动将刚才写好的散装诊断代码重构，包裹进 `def run(**kwargs):` 的入口函数规范里；
2. 内部生成代码写入并存入 `~/.byoe/skills/project_doctor.py`；
3. **闭环完成**：以后你再遇到问题报错，只需发令指令：“调用 `project_doctor` 帮我排查一下”，AI 便会无缝读取自身沉淀的动作技能帮你一键排障。

## 三、管理与维护建议

由于所有的经历、沉淀的脚本都以普通文件留存在本地目录：
- **查看**：你可以通过终端使用 `ls ~/.byoe/skills/` 直接查看累积的资产。
- **可视化**：也可以通过 BYOE Web 界面进行直观的增删改查。
- **共享与团队同步**：强烈建议将你的 `~/.byoe/skills/` 初始化为一个独立的 Git 私人仓库（或放入项目的 `.byoe` 环境配置库下做软连）。这样在团队不同的开发者电脑之间，只需 `clone` 这个目录，就能实现整个团队“数字大脑”和诊断技能库级的秒级共享！

## 四、Trigger（触发词）自动注入机制

> v0.7.2 起，技能触发词从"AI 自行感知"升级为**确定性自动注入**。

### 工作原理

每次用户发送消息时，BYOE 引擎会扫描 `~/.byoe/skills/` 目录，将**所有含 `trigger` 字段的 JSON 技能**的触发词与用户输入进行匹配（大小写不敏感，支持中英文）。

一旦命中，该技能的 `instructions` 内容会自动 **注入当前对话的系统提示词**，无需用户手动激活。

```
用户消息: "帮我审查API接口设计"
                    ↓
引擎扫描 ~/.byoe/skills/*.json
发现 api-reviewer.json 的 trigger = "审查API"    ← 命中！
                    ↓
api-reviewer.json 的 instructions 注入 system prompt
                    ↓
AI 回复时自动遵循 RESTful API 审查规范
```

### 编写高质量 Trigger

```json
{
  "name": "db-design-standard",
  "trigger": "设计新表",
  "instructions": "设计数据库表时，必须遵循以下规范：\n1. 必须有 id、created_at、updated_at 三个基础字段..."
}
```

**Trigger 设计建议**：
- 使用**自然语言短语**而非单个词，如 `"审查API"` 优于 `"API"`；
- 触发词越具体，误触概率越低；
- 同一对话中可同时触发多个技能（多个 instructions 叠加注入）；
- 技能在该轮回复结束后自动恢复原始 system prompt，不影响下一轮对话。

### 与手动激活的区别

| 方式 | 触发方式 | 持久性 | 适用场景 |
|------|---------|--------|---------|
| **自动 Trigger** | 检测到触发词时自动注入 | 仅当前轮 | 上下文相关的一次性增强 |
| **手动激活** (`/skill <name>`) | 显式命令 | 整个会话 | 需要持续生效的全局规范 |
| **面板激活** | Web UI Skills 面板点击 | 整个会话 | 可视化管理 |

## 五、技能 LRU 自动清理

技能上限默认 **50 个**。超出时系统自动清理**最久未使用**的技能（按 `last_used` 时间戳排序），而不是简单地删除文件名最旧的。

每次 `get_skill()` 调用时，引擎会自动更新对应技能的 `last_used` 时间戳和 `use_count` 计数：

```json
{
  "name": "api-reviewer",
  "use_count": 23,
  "last_used": "2026-06-28T14:33:00Z"
}
```

**建议**：高频使用的核心技能（如代码规范、项目风格指南）会因使用频率高而自然保留；低频的一次性技能自动淘汰，无需手动管理。
